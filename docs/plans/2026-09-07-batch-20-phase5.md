## Task derivation from the spec

Ordering principle: PORT BEFORE RETIRE — the cargo test surface
lands first so no coverage gap ever exists in the tree; the
retirement consumes the T1 mapping; the sweep runs last against
the finished world.

### T1 — the mapping and the cargo port layer (spec §2's port
half)

The mapping enumeration FIRST (the closure artifact): every
tests/*.test.mjs listed with its fate — ported-to-cargo or
retired-with-subject — plus what covers each ported case.
Then the ports, pins kept at full strength
(quality.pin-copies-byte-exact; byte equality, no
normalization): the dogfood suite (KIT_OWNED root/template
parity, generated-file freshness via render --check semantics,
seed-once pins incl. the three eval scenarios), the commit-msg
hook tests (the capability probe, the degrade arm, the trailer
gate — process-spawning cargo tests with scratch repos), the
retired-paths contract (the shared source collapses into the
Rust constant's own test surface). Nothing retires in T1; the
vitest suite still runs green beside the new cargo tests
(double coverage is the safe intermediate state, disclosed).
