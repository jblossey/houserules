## The four consequential design points (plan-level rulings,
approved with this plan)

1. PAYLOAD EMBEDDING: the binary carries `template/` embedded at
   build time (include_dir or build.rs + include_bytes — T3 vets
   and pins the mechanism). The embedded payload is the
   POST-REWRITE payload: flat commands, no tools/*.sh.
2. CORPUS SPLIT AT THE REWRITE BOUNDARY: the reference rewrite is
   the spec's sanctioned exception, so the frozen-JS contract ENDS
   for surfaces whose output embeds command references. The render
   goldens move out of the frozen corpus into Rust-generated,
   reviewed goldens (tests/goldens/render/), regenerated by a
   cargo dev command; make-corpus drops its render slices; the
   frozen corpus keeps every slice whose bytes carry no command
   reference (checks, audit, validate, stats, backlog). THE
   DIFF-SHAPE GATE proves the re-baseline is exactly the rewrite:
   a retained script asserts old-corpus vs new-golden diffs
   contain ONLY lines matching the kb.sh/backlog.sh -> houserules
   mapping table (the closure-claims rule applied to the rewrite
   itself).
3. REPO SELF-FLIP: dogfooding the phase-3 update deletes this
   repository's own root shell tools, so the repo's gates, CI,
   CLAUDE.md, mise tasks, settings hook, and the controller
   workflow flip to `houserules` commands in the same task (T6),
   with the binary provided via cargo (a mise task builds and
   fronts it). template/tools/*.mjs stay through phase 4 (the live
   vitest gates and corpus regeneration drive the frozen and live
   JS) and retire at phase 5.
4. HR-051(a) RESOLVED DETERMINISTIC, RUST-ONLY: the Rust validate's
   checkTaskReportAudit extends to scan fix_rounds[].tests[].output
   for an audit summary carrying nonzero skipped (batch 17 hit the
   shape twice). The frozen corpus slices are unaffected
   (additive); the live kb.mjs stays frozen-in-behavior; recorded
   as a post-port improvement in spec §6 when it lands.
