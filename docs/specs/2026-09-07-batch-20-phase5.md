## 1. Goal

After this batch the repository and the kit are one static
binary plus POSIX shell, in development as in adoption: no
bin/houserules.mjs, no frozen JS corpus, no make-corpus, no
package.json/pnpm/node_modules/vitest, no node or pnpm mise
pins. HR-047 — the Tier-2 rewrite — closes. The batch ends with
the ruled §5.24 full-repository sweep and its mechanical
residue gate (the §5.39 discipline: the enumeration is of the
old form's residue).

## 2. What retires (each with its reason recorded)

- bin/houserules.mjs — the frozen reference; its remaining
  consumers (the frozen-worktree tests) retire with it.
- tests/corpus/** and tools/make-corpus.mjs — the parity
  contract's remaining slices (audit/validate/stats/backlog/
  read-not-carrying-the-command-string) end their service; the
  §5.35 interim exception closes. Boundary correction
  (controller, 2026-09-07, from the T1 r2 review): the goldens
  do NOT already cover these commands — tests/goldens/ holds
  check, render and read-for only. The remaining slices
  therefore leave the frozen contract the same way the first
  three did (the batch-18 §3 criterion): T3's FIRST act
  re-baselines them as reviewed, Rust-generated goldens via
  gen-goldens (backlog list/get/batch/set/check-backlog, kb
  topics/index/index-standing/standing/get, validate/stats/
  audit), and the parity suites flip to golden-reading in the
  SAME commit as the corpus deletion — a reading test never
  outlives, nor precedes the replacement of, the artifact it
  reads. Only then does the corpus retire.
- The vitest layer: every tests/*.test.mjs is enumerated and
  mapped — PORT to cargo (the dogfood byte-pin suite: KIT_OWNED
  parity, generated-file freshness, seed-once pins incl. the
  eval scenarios; the commit-msg hook tests; the retired-paths
  contract) or RETIRE WITH ITS SUBJECT (the corpus tests, the
  frozen-worktree init/update tests, kb/backlog engine tests
  whose subject is the retiring .mjs engines). The enumeration
  is the closure artifact; no test's coverage is silently
  dropped — each row says ported-to or retired-with.
- package.json, pnpm-lock.yaml, vitest configs, the node/pnpm
  mise pins, the coverage-floor machinery (the ratchet's story
  ends with vitest; the record states it — cargo's suites are
  the ongoing gate).
- template/tools/kb.mjs, backlog.mjs, tools/lib/** — the
  shipped-but-inert engines (spec §5.23's retirement point);
  KIT_OWNED and the ownership docs update; update deletes them
  from installs via RETIRED (the T4/T5 mechanism's second use).
- CI: the pnpm/node steps leave; CONTRIBUTING and the runbook
  update; the npm-era knowledge entries amend or retire under
  recorded rulings (houserules.node-under-mise,
  houserules.pnpm-only's scope, live-run-recipe residue, the
  vitest-coverage gotcha) — ids permanent, bodies restated,
  standing changes listed for the owner where a standing entry
  amends.

## 3. HR-066 — the checker ships through the binary

check-report-claims moves behind the flat surface (a
`houserules` subcommand or an equivalent shipped form — the
task defends the shape) so the seeded implementer template's
closing act runs in every adopter repo. The payload invariant's
second known-gap bullet retires. The template edit pays the
shared evals rerun this batch owes anyway (§6).

## 4. HR-071 — the paste-run lint

The checker gains the bounded no-execution lint over command
fields: angle-bracket placeholders, prose appended after the
command, a failed shlex-style parse. An honest Limits bullet
states what it cannot see (a retyped command that still
parses). Lands in the same code the HR-066 move touches.

## 5. HR-067 — the orchestrating-skill clauses

Both clauses land in the skill (template + root): the relay
rule (a fix-round dispatch quotes a finding's premise only with
its named verification run beside it; absent that, the
implementer measures first) and the brief rule (a brief's claim
about file contents is measured at brief-writing time). Rides
this batch because the template edits already pay the evals
rerun.

## 6. The evals rerun

Template-touching batch: ONE shared rerun at the final template
state before the branch review (the ledgered economy), the
record at the new blobs.

## 7. The closing sweep (§5.24 + §5.31, ruled)

The batch's last task: the full-repository scan correcting
every rule, knowledge entry, backlog item, and doc (README
included) to the post-JS world; historical records keep their
wording; the §5.31 library-governance pass over the
until-now-untouched remainder (name what custom code a
well-maintained library should replace, escalate candidates);
and the mechanical residue gate per §5.39 — the zero-hit sweep
of the retired forms (node/npm/pnpm/npx/vitest/.mjs invocation
patterns and their variants) outside sanctioned history, as a
rerunnable cargo bin or an extension of find-shell-tool-refs,
retained as a permanent gate.

## 8. Library posture (research at spec time)

No new library: the ports are byte compares and process
plumbing on std + the crate's existing dependencies; the
checker move relocates existing code. Anything an implementer
believes needs a crate escalates per the governance rule.

## 9. Risks and bounds

- The corpus retirement removes the JS-parity net; the goldens
  + cargo suites carry the gate from here — the spec states
  this as the accepted trade (the parity contract COMPLETED its
  purpose: every surface was ported byte-identical and the
  divergences ruled).
- The dogfood port must keep every pin's strength: byte
  equality, no normalization (quality.pin-copies-byte-exact
  governs the port).
- mise drops node/pnpm: every doc that names them updates; the
  §5.24 sweep is the net.
- The evals scenarios' setup lines that assume package.json
  (dependency-add) need an honest post-JS restatement — the
  scenario edit pays its rerun in the same batch.

## 10. Acceptance

The repository builds, tests, lints, and gates through cargo
and the binary alone in a tree with no package.json; a fresh
`houserules init` adopter repo carries no JS; the residue gate
runs zero-hit; HR-047 ticks done with Tier 2's completion
recorded; the branch review (fable) and the standing finish.
