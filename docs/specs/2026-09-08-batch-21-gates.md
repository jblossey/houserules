## 1. Goal

Every gate improvement in this batch converts a defect class a
batch-20 reviewer caught by hand into a deterministic check that
fires on its own. Each item cites the incident that produced it;
each lands with a seeded-instance RED and a clean run at HEAD as
its acceptance.

## 2. HR-074 — the dead-glob gate (check-knowledge)

check-knowledge fails when an area's paths globs match zero
files in the tracked tree, naming the area and the dead globs.
Incident: cli's `bin/**` matched nothing from the T3 retirement
until the fix round, silently orphaning two entries (one
carrying the live_run report check). Design note: the `process`
area's deliberately empty paths list must stay legal — the gate
distinguishes "declared empty" from "declares globs that match
nothing".

## 3. HR-075 — the ephemeral-path check (check-report-claims)

The checker flags a cited artifact path under /tmp/ or a
session-scratchpad pattern in any scanned narrative field.
Incident: T3's goldens enumeration cited /tmp and cost a fix
round; T1's review had filed the same class before that.
Deterministic, near-zero false-positive risk; an honest Limits
bullet states what it cannot see.

## 4. HR-076 — the emitter round-trip (check-backlog)

check-backlog verifies each backlog JSON file round-trips
byte-identical through the shipped emitter (parse, re-emit,
compare); a divergence fails with the file named. Incident: the
HR-047 tick re-serialized kit.json with ASCII escapes and only
the branch review caught it.

## 5. HR-077 — the sanctioned-fail annotation (audit)

`houserules audit` gains a machine-readable annotation (shape
defended by the task against the current CLI grammar — e.g.
`--sanctioned <rule>=<ref>`) echoed in the JSON row's evidence,
so a spec-booked interim fail is declared once per dispatch and
read downstream instead of re-narrated. Incident: batch 20's one
sanctioned evals red was re-explained by hand in 14 audits and
review rounds.

## 6. HR-086 — the degenerate-textList guard

Batch 20 T6 proved `houserules validate` and
`check-report-claims` both pass a report whose self_review holds
one string per character. PROPOSED RESOLUTION for the gate (the
owner rules it here): a minLength on textList items in
`.claude/schemas/deliverables.json`, BOTH copies (template +
root) — deterministic, enforced everywhere validate already
runs, no new checker heuristic; the checker stays unchanged. The
nine-field blast radius enumeration from HR-086's body bounds
the change; existing corpus fixtures re-validate after (the
task proves no tracked fixture regresses).

## 7. HR-079 — walkdir (ruled §5.47)

Adopt walkdir exact-pinned via `cargo add walkdir@=<resolved>`
as a dev-dependency (vetting recorded per
security-hygiene.dependency-vetting at adoption time, the
§5.47 evidence refreshed) and replace the duplicated walkers:
find-shell-tool-refs.rs's `walk_files` and diff-shape-gate.rs's
variant. Behavior pinned by the bins' existing gates before and
after (their clean runs byte-compare).

CORRECTION (batch 21 T3 fix round 1, review-ruled sound): "as a
dev-dependency" above cannot compile. A `src/bin/*.rs` target
never links `[dev-dependencies]` -- Cargo makes those visible
only to test/bench/example builds -- so walkdir lands under
`[dependencies]` instead. It was already a normal transitive
dependency of rust-embed (via rust-embed-utils) at the same
pinned version, so the shipped `houserules` binary's footprint
does not change. For the record: an `examples/` target does see
`[dev-dependencies]` (verified), a larger restructure nobody
licensed here.

## 8. Library posture

walkdir =2.5.0 enters under the §5.47 owner ruling — the one
adoption; everything else is std on the crate's existing
dependencies. Anything more escalates per
quality.well-maintained-libraries.

## 9. Risks and bounds

- Gate false positives: each new gate ships with the bounded
  enumeration of what it flags at HEAD (expected: zero) and a
  Limits statement where a class is knowingly invisible.
- The schema minLength touches adopter-facing validation: the
  seeded schema changes in the same commit as the root, and a
  fresh-init seed re-validates its own deliverables examples if
  any exist.
- HR-077 changes audit's CLI surface: the runbook/skill
  references to audit invocations sweep in the same task.

## 10. Acceptance

Each gate: a seeded instance of its incident class goes RED
under the new gate (verbatim), and the gate runs clean at HEAD;
the full suite, the binary's gates, and `mise run lint` green;
walkdir's replacement leaves both bins' clean runs
byte-identical; live run per process.live-run-before-ci; the
standing finish.
