# Batch 18 spec: Tier-2 phase 3 — the payload flips to the binary

Date: 2026-09-05. Status: draft, pending owner approval.
Parent: docs/specs/2026-09-04-batch-15-tier2-spec.md §5.3 (approved),
plus the §2 invariant amendment re-timed here at the batch 16
branch review. Items: HR-062 (under HR-047), HR-060, HR-061,
HR-051. This spec elevates the phase's contract-changing decisions
out of the plan and puts them under the owner's gate; the plan
(docs/plans/2026-09-05-batch-18-phase3.md) derives from it.

## 1. Goal

After this batch, an adopter needs only the `houserules` binary:
`init` seeds a project, `update` maintains it (now including
deletion of retired kit files), `files` prints the ownership
split, and every shipped reference — CLAUDE.md, skills, agent
templates, generated rules, the hook — invokes the flat
`houserules` commands. `tools/kb.sh` and `tools/backlog.sh` leave
the payload and leave existing installs at their next update. The
commit hook's commitlint probe becomes `houserules check-commit`.
The payload contract ruled at the Tier-2 spec's approval ("the
binary and POSIX shell only") becomes TRUE and its invariant
amendment lands.

## 2. Decision: the payload lives inside the binary

`init` must materialize `template/` without a package manager or a
checkout, so the payload embeds at build time (`include_dir` or a
build.rs with include_bytes — the implementer vets both against
current docs and pins the choice; either way the payload is
byte-addressable at runtime and the binary stays one file). What
embeds is the POST-REWRITE payload. Consequence: a payload edit
requires a rebuild; the dogfood pins (root copies byte-equal to
template/) keep their meaning, with the binary as the copier.

## 3. Decision: the frozen-JS contract ends at the rewrite boundary

The reference rewrite is the sanctioned exception the parent spec
names. Where rewritten references reach generated OUTPUT (the
rendered rules' `Detail:` line, the skill's retrieval protocol,
`standing`'s command string), the frozen JS can no longer produce
the expected bytes. Therefore:

- The corpus SPLITS: every slice whose bytes carry no command
  reference (check messages, audit JSON, validate verdicts, stats,
  backlog outputs) stays frozen-JS-pinned and regenerable exactly
  as today. The render goldens move out of the frozen corpus into
  reviewed, Rust-generated goldens (`tests/goldens/render/`),
  regenerated by a cargo dev command; make-corpus drops its render
  slices.
- THE DIFF-SHAPE GATE proves the re-baseline is only the rewrite:
  a retained, rerunnable script diffs the old corpus render slices
  against the new goldens and asserts every changed line matches
  the explicit `tools/kb.sh <cmd>` → `houserules <flat>` /
  `tools/backlog.sh <cmd>` → `houserules <flat>` mapping table —
  no other byte moves. The script and its clean run are the
  batch's closure artifact for the rewrite
  (process.closure-claims-carry-enumeration applied to the rewrite
  itself).

## 4. Decision: the repository flips itself in this batch

Dogfooding the new `update` deletes this repository's own root
`tools/kb.sh` and `tools/backlog.sh`. In the same task, the
repository's CLAUDE.md, mise tasks, CI checks job, SessionStart
hook settings, and the controller's documented ritual flip to
`houserules` commands, with the binary supplied by a mise task
that fronts `cargo run`/a locally built binary. commitlint leaves
the repo's CI in favor of `check-commit`. What does NOT flip yet:
`template/tools/kb.mjs` and `backlog.mjs` stay shipped-but-inert
through phase 4 — the corpus regeneration (frozen JS) and the live
vitest gates still drive them — and retire at phase 5 with the
rest of the JS. `tools/make-corpus.mjs` remains the ruled interim
exception (design.md §5.30).

## 5. Decision: HR-051(a) lands deterministic, in the Rust validate
only

`checkTaskReportAudit`'s Rust port extends to scan
`fix_rounds[].tests[].output` for an audit summary carrying a
nonzero `skipped` (the batch-12 shape; it recurred twice in batch
17). Additive: no frozen corpus slice is affected, the live kb.mjs
stays behaviorally frozen, and the extension is recorded in the
parent spec's §6 as a post-port improvement when it lands, pinned
by its own fixtures. HR-051(b) (the verbatim-output invariant
lifted onto its own line) rides the T1 template work.

## 6. check-commit

Reuses the audit's `commits` rules (subject pattern, body line
max). CLI shape settles in its task against how the hook and CI
actually call commitlint today (a message file from the hook; a
range in CI). The shipped hook probes the binary and degrades to
the trailer gate alone, exactly as the commitlint probe does now.

## 7. The process items riding the batch

- HR-061: the report-claims checker becomes a cargo bin (same five
  checks, the honest Limits, the unresolvable-sha error); the
  `.mjs` and its vitest test are deleted; the standing bullet's
  invocation updates. CI wiring resolved: the checker gates
  gitignored workspace reports, so there is no CI job — the
  closing-act mandate is the whole mechanism.
- HR-060: implementer.md gains the audits-WITH---report clause and
  the checker closing act; task-reviewer.md gains
  verify-by-running. One shared evals rerun covers all template
  changes (HR-051's included).

## 8. What does not change

The flat command surface and every batch-16/17 parity contract on
non-rewritten bytes; the knowledge/backlog data formats; the
release machinery (phase 4); the frozen corpus mechanism for
everything below the rewrite boundary; the batch process itself.

## 9. Out of scope

Phase 4 (delivery: cargo-dist wiring, the tag flip, HR-049, macOS
signing) and phase 5 (full JS retirement, the repository sweep,
the coverage configs' retirement); HR-053 modularity; any behavior
change beyond §5's named extension and the rewrite.

## 10. Acceptance

A scratch adopter flow proves the goal end to end: `houserules
init` a fresh repo, run its checks through the binary, `houserules
update` over an OLD JS-kit install and watch the shell tools leave
and only kit-owned files change; this repository runs its own
gates through the binary; three-OS CI green; the invariant
amendment merged.
